# 模拟信号建模：可完善与可拓展之处

三个并行审计（物理保真 / 验证完整性 / 链路覆盖）+ 我自己的结构性扫描。
**每一条都经过验证才写入**，包括我自己的结论。

---

## 一、三个审计一致指向的同一个结构性事实

> **这是一串「信号变换」，不是一组「有状态的具名器件」。**
> 没有任何阶段会读取另一个器件的**状态**。

这一条解释了下面几乎所有缺口。

而它直接关系到你最初的目标——"**这条链在某处坏了**"：

| 今天能回答 | 今天**不能**回答 |
|---|---|
| 故障**在哪一环被注入** | 把带子翻录到另一台机器上，**痕迹还在不在** |

因为「录进磁带的」和「只在播放时存在的」没有被区分——**虽然是代码注释里写明的原则，但没有被强制执行，也没有暴露给使用者**。

**这是性价比最高的一项改动**：把每个机制标记为 `recorded_on_tape` 或 `playback_only`，在缺陷时间线上暴露出来。**不需要新参数**。

## 二、我自己扫出来的：可达性问题

```
connector 层: 0 个预设使用     ← 整套受潮/锈蚀物理只能手动拖滑杆
84 / 150 个参数没有任何预设设置
```

## 四、按「真实感增益 / 工作量」排序的缺口

### Tier 1 — 高增益，低工作量

| # | 缺口 | 现状 | 为什么真实链路有 | 可见后果 |
|---|---|---|---|---|
| **1** | **失落补偿器（DOC）** | 失落处填固定平台 `0.72+0.30·noise` | 真实录像机用 **1H 延迟线**补**前一行**，所以失落看起来是**拖影重复行**，白条是少数 | 模型在任何设置下都显示**未补偿**的白条，永远做不出"被补偿"的样子 |
| **2** | **亮度 FM 调制与削顶** | 介质把复合信号当**基带**处理，从不做 FM | VHS 把亮度写成 **FM 载波**，偏摆范围有**上下削顶**，所以有硬白削顶、**反相白条**、暗部噪声远差于亮部 | 无白削顶、无反相白条、噪声不随电平变化 |
| **3** | **色同步门 + ACC/APC + 消色器** | 没有逐行 burst 估计，`chroma_loss` 是几何抽样 | 弱 burst 会让 ACC/消色器**整行/整场丢色**，这是极常见的真实故障 | 做不出"颜色掉一行又回来"，也做不出电视切黑白 |

**这三项都有现成基础**：1H 延迟已在 `split_composite` 里用了；`fm_carrier_mhz` **已声明却只被打印**；`chroma_under_luma()`（色副载波降频）**定义了但从未被调用**。

### Tier 2 — 高增益，中等工作量

**4. 磁带位置 / 磁带寿命 — 我认为这是**概念上**最重要的一项。**
今天一切以**帧序号**为锚：划痕随 `sin(frame_index*0.045)` 漂移，`stiction_stretch` 按**片段时长比例**偏置。而真实缺陷**在磁带上的某个位置**——每次走带都在同一处复现、快进时更早出现、倒带时**逆序**出现。加一个单调的 `tape_pos` 就是**"一个 VHS 效果"变成"这一盘带"**的关键。

**5. 磁头—磁带耦合：方位角损失、间距损失、重放均衡** —— 今天没有任何机制取决于磁头**离磁带多近**。~0.1° 偏航在 1µm 波长上就是**短波长被抹掉**，所以真实失跟踪是**颜色与细节先死**、按波长整形；模型只是**平坦衰减**。

**6. RF AGC / 同步顶钳位 / 同步分离器** —— `agc_range` **已声明却从未被读取**；没有 AGC 攻击/释放，所以没有**呼吸噪声**和黑电平泵动；没有同步分离器，所以同步幅度不影响光栅位置。

**7. 录在带上 vs 只在机器里**（见第一节）——**最便宜的"切题"改动**。

**8. 数字侧：ECC 失败与错误隐藏的传播** —— DV 有 `augment_blockiness` **已实现却从未被调用**；`_apply_digital_damage` 只是 numpy 行拷贝，不是解码器。MPEG-1 **没有比特流错误**，所以 VCD 最标志性的故障（损坏宏块**通过 P 帧预测器向前扩散**）**不可达**——而 `self._prev_luma` 已经是解码后的平面，改动很小。

**9. TBC 作为真实的有缓冲器件** —— 今天是四个标量混入相位数组。真实 TBC **只能在窗口内纠正**，超出就**丢帧或冻结**。所以"**TBC 让烂带更糟**"无法表达。

**10. 色度：降频载波频差 + 微分增益/相位** —— 色度骑在亮度 FM 上，亮度增益压缩会带动色度，这就是**同一帧内颜色随亮度变化**的原因。今天色度是独立平面 + 标量增益，**DG/DP 结构上不可能**。

**11. CRT 荫罩/点距与会聚** —— 显示层已经很全（几何、散焦、泛光、伽马、扫描线、隔行、过扫描、暗角、反射、CRT 受潮/色偏/偏转），但**没有荫罩采样结构**和**电子束落点/会聚误差**。"采样摩尔纹"正是这一项。

### Tier 3

**12** 磁头堵塞**动力学**（真实是"几秒内累积、突然清除"，今天是静态行轮廓 + 正弦摆动）
**13** **音频完全不存在**（而同一走带故障**本该同时**影响画面与声音）
**14** 多代翻录（执行器从 **RGB** 重建中间节点，丢掉了复合信号的接点）
**15** 相邻磁迹串扰（保护带溢出）

## 五、审计发现、我已修复的缺陷

| 缺陷 | 数量 | 危害 |
|---|---|---|
| **故障目录引用不存在的参数** | 3 个 | 点症状会跳到**另一个机制**，覆盖计数器却报"已覆盖" |
| **同层重复定义** | 12 个 | 后定义覆盖前定义，**说明文字被丢弃**，且两份已漂移 |
| **说明文字引用了已撤回的测量** | 1 个 | `row_timebase` 声称"实测标定"，而那批数字项目自己已撤回 |
| **测试死代码的检查** | 1 个 | 检查了一个**零调用点**的函数 |
| **被字符串绕过的检查** | 1 个 | 用**子串搜索**判断路径是否调用转换，删掉调用仍然通过 |
| **`line_jitter` 无任何检查覆盖** | — | 它可以完全失效而**套件全绿**（实测它是活的） |

**我在修"重复定义"时自己犯了一个错**：想把两份漂移的说明文字**合并**以免丢信息，结果拼出了**句子碎片**（`shuttle_mode` 变成 4 句旧版 + 3 句新版）。已回退——保留一直生效的那版，**可见信息一点没丢**。

## 六、如果只做三件事

1. **区分「录在带上」与「只在机器里」**（Tier 2 #7）—— 最便宜、最切题，直接回答"翻录后痕迹还在不在"
2. **失落补偿器 + 亮度 FM 削顶**（Tier 1 #1 #2）—— 都有现成基础，是"消费级 VHS **看起来像**消费级 VHS"的两块基石
3. **让 connector 层进入预设，并做一次标定** —— 物理最丰富的一层，今天**零预设、零标定**

**我建议从第 1 项开始**，因为它不增加参数、不改架构，而是**让模型能诚实地描述自己**——这正是这个项目一直在做的事。

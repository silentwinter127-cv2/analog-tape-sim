# 来自 ntsc-rs 的建模启示

对象：`side.png`（左 ntsc-rs，右另一模型）及其观察记录。
方法：**读 ntsc-rs 的实际源码**，把每个可见现象映射到**信号运算**，再映射到**物理器件**，
最后对照本模型已有的东西。

---

## 一、先修正一条观察

观察记录的第 2 条判断是：「色度按 **[行块]** 整组错，而不是逐像素错，色带很宽（30–50 行），
排除了逐行独立噪声」。

**方向对，但归因需要改。** 读了源码后可以确定：

> **那 30–50 行的"高"不是垂直滤波造成的，而是水平色度带宽造成的。**

算一下（NTSC 227.5 周期/有效行、720 采样/行）：

| 滤波器 | 带宽 | 每周期像素 | 完成一次过渡 |
|---|---|---|---|
| ntsc-rs I | 1.3 MHz | 8.7 px | **≈4 px** |
| ntsc-rs Q | 0.6 MHz | 18.9 px | **≈9 px** |
| 本模型 `chroma_bandwidth` 默认 | 0.75 MHz | 15.1 px | **≈7.6 px** |

**色度沿行方向只能缓慢变化**，所以屏幕上任何颜色变化都是**一条横向延伸的宽带**。
**带的"高"是画面本身的属性**（天空渐变、墙面），**不是垂直模糊的证据**。

**而且 ntsc-rs 的 VHS 路径里没有垂直色度滤波**：`chroma_delay` 的垂直分量来自
`VHSTapeParams`，而真实 VHS 前端是 **1H 延迟线——纯水平**，垂直分量为零。

**这条修正很重要**：按原判断会去建一个**被模仿对象本身也没有**的垂直色度机制。

**顺带一个反直觉结论**：本模型的色度带宽（0.75 MHz）**落在 ntsc-rs 的 I 与 Q 之间**，
所以**水平色度限带不是两者的差距**。

## 二、现象 → 信号运算 → 物理器件

| # | 观察到的现象 | ntsc-rs 的**信号运算** | 物理器件 | 本模型 |
|---|---|---|---|---|
| 1 | **大面积偏色**（左下建筑整体蓝紫），且不跟轮廓 | `chroma_phase_error`：I/Q 整体旋转 | **色度相位误差**（APC 失锁 / 色同步相位误差） | ✅ 有 `chroma_phase_error` |
| 2 | 同上 | `chroma_delay(horiz, vert)` | **色度群延迟**（Y/C 时延不等） | ✅ 有（但见第四节） |
| 3 | **顶部高对比边缘的波动状黑边** | `vhs_edge_wave`：每行按 FBM 噪声水平位移 | **走带波动**（时基误差） | ✅ 有 `line_jitter` / `walk` |
| 4 | **同一处的彩色镶边** | `luma_into_chroma` **解调器拓扑**：box（±2 px）/ 2-D FIR（±2 px、±1 行） | **梳状滤波器/延迟线解调**的分离残差 | ⚠️ **只有一种拓扑** |
| 5 | 亮度与轮廓**保持正常** | 亮度未经受色度那些操作 | —— | ✅ 一致 |

**第 4 条是本模型真正的缺口。** ntsc-rs 的解调器是**可选的四种拓扑**：

```
box      : 亮度 = 4 个采样（跨 ±2 px）的均值
1-line   : 亮度 = 本行与上一行的均值
2-line   : 亮度 = 0.5×本行 + 0.25×上一行 + 0.25×下一行
2-D FIR  : 横向 ±2 px、纵向 ±1 行
```

**本模型只有一种**：1H 延迟线梳状 + 带通分离，用 `comb_depth` 混合。

**box 和 2-D FIR 正是产生"边缘彩色镶边"的拓扑**——因为它们的冲激响应**在水平方向跨 ±2 像素**，
所以**高对比边缘的色度残差会横跨 4 像素**，读起来就是彩边。

**这个缺口是本模型"缺一个器件"，而不是"缺一个参数"**：真实接收机确实在这几种分离方案之间
选择（简单带通 / 1H 梳状 / 2H 梳状 / 2-D 梳状），而**选哪一种决定了边缘彩边的形态**。

## 三、我做过但失败的两件事（诚实记录）

**1. 我试图从 `side.png` 量出垂直色度展宽。两次都失败了。**

- 第一次用"自相关在 lag 16–32 仍为正"作判据 → **无效**：天空和墙面是平滑渐变，
  它们的颜色**本来就**在几十行尺度上自相关，**与是否递归滤波无关**。仪器在测内容。
- 第二次改用"冲激响应尾部 vs 高斯参考" → 两个面板的比值**都是 6× / 3000×**，
  **没有分离**，因为两图都有真实的竖向结构。

**结论：这个量从这两张图上测不出来。** 我没有硬报一个数字。

**2. 我在同一个输出里写了自相矛盾的数字。**

脚本算出 Q 带宽的过渡是 **9.4 px**，而我手写的结论句说"约 40 px"。
**两者在同一个输出里互相矛盾**——而这类错误之所以能活下来，正是因为
**人记住的是散文里的数字，不是计算出的数字**。已修正。

## 四、另外两处结构性差异（源码可证）

**1. `chroma_vert_blend` 是递归 IIR，本模型是一次高斯 FIR。**

```rust
// ntsc-rs：delay 里存的是"已经被混合过"的上一行 → 反馈
*i = (delay_i[index] + c_i) * 0.5;
delay_i[index] = c_i;
```

本模型：`i = (1-k)*i + k*lowpass(i, 1.35, axis=0)`——**一次 σ=1.35 行的高斯，有限冲激响应**。

**两者物理上都真实**，但**行为不同**：递归版把单行色度事件展开成 `0.5^n` 的指数长尾，
有限版在约 4 行内就归零。**不过第二节已说明：这不能解释那张图的宽带**，所以
**我不建议为了那张图去改它**——这是一个**独立的、待单独判断**的差异。

**2. VHS 带速滤波的已知问题。**

源码自己标注：`// TODO: use a better filter! this effect's output looks way more smeared than real
VHS`。而且 `filter_plane` 用 `InitialCondition::Zero` 起滤，源码也承认"**左边会留一条线**，
这在原始 C++ 和 Python 版里都有，但大概不是真实 VHS"。

**这两条说明 ntsc-rs 自己知道它的 VHS 滤波不够物理**——所以**不应该以它的观感作为标定目标**。

## 五、结论：值不值得做，以及做什么

**值得做的只有一项**：把**色度解调器拓扑**做成可选器件（对应第二节第 4 条）。

- 它是**真实存在的选择**，不是效果旋钮：简单带通 / 1H / 2H / 2-D 是不同年代的接收机方案
- 它**只影响边缘彩边的形态**，不影响色彩本身——正好对应观察里"亮度正常、彩边在边缘"
- 工作量中等：`core/signal.py` 已有 `split_composite`/`demod_chroma`，加 2–3 种拓扑即可
- 与项目原则一致：**新增器件，不是新增效果**

**不建议为这张图做的**：
- 垂直色度展宽——**被模仿对象没有这个机制**
- 改色度带宽——**已经在同一区间，不是差距**

**需要单独判断的**：递归 vs 有限垂直色度混合（第四节第 1 条）。
它**真实**，但**与这张图无关**，应当按它自己的物理证据来决定，而不是被这张图带着走。

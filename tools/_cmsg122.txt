**The fault this round fixed.** The mode's settings were applied inside the camera stage, so the renderer used them and
**nothing that read the parameters could see them**: measured in the browser, mode 3 selected with the engine's state
reporting `nv_green_mix = 1` while the renderer used 0 -- **two sources of truth for one picture**, with the panel's
slider editing a parameter the mode owned.

**The fix is in `Project.resolved_params`**, and its own docstring is the reason: device individual variation is applied
there "so that every caller goes through it and none can forget" -- the same problem, already solved once for a different
kind of per-project adjustment. **Verified by driving the page:**

    mode 0 -> {nv_green_mix 1, nv_accumulate 8}    the defaults, unchanged
    mode 1 -> {nv_green_mix 1, nv_accumulate 1}    one frame, as NightShot should be
    mode 3 -> {nv_green_mix 0, nv_accumulate 8}    the green display off, as colour requires

**Four faults were found getting there, and three were faults in my own tooling:**

  * **the resolver wrote unprefixed keys** -- the module's preset uses `NightVisionSpec` field names (`accumulate`,
    `green_mix`, `illuminator`) while the parameter set uses `nv_`-prefixed ones, so it added three keys nothing reads
    and left the real three at their defaults. **The key-by-key diff is what showed it**, and the guard meant to prevent
    it compared `f"nv_{k}"` against a set while using the bare `k`, so it passed everything through;
  * **the helper landed between `@dataclass` and its class**, so the decorator attached to the function --
    `'function' object has no attribute '__mro__'`. A textual anchor naming a class does not name everything it depends
    on;
  * **probes read `d.project.params` instead of `d.params`** -- the stored set versus the resolved one -- and reported a
    fault that had already been fixed, twice including after the fix;
  * **a regex could not match the text it was written from**, because `fmt(val)` and `fmt(nv)` contain unescaped
    parentheses. A diagnostic printing each line separately confirmed every line was present while the pattern was not,
    and **ruled out a stale file**: the disk and served copies are byte-for-byte identical.

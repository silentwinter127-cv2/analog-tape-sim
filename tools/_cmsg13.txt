add a canvas build stamp and a live drag diagnostic

Two things have been impossible to establish from this side, and both cost a round trip
through a screen recording to settle:

**Which build a browser is running.** The server has been verified to serve the fixed file --
23680 bytes, the right markers present -- but a cached page looks identical from here. One
earlier recording settled it by accident: its footer showed the `02c 接口` label, which had been
added in the commit a minute before, and that proved the page was current. Nothing has proved it
since. The canvas now prints a build stamp to the console on load, so "which version is this"
is answered by looking rather than by inference.

**Whether a drag is still wrong, and in which way.** Reading it off a recording works but costs
a round trip. The page can measure it directly, and the error's *shape* is the diagnostic:

    constant regardless of the cursor   -> a units mistake in the offset
    growing as the cursor moves away    -> a transform mistake
    zero                                -> the drag is correct

So a drag that follows the pointer prints nothing and one that does not prints how far off it
is. That distinction is what took three recordings to establish the last time, and it is one
line of arithmetic on values already in hand.

**Two mistakes in the check itself, both worth recording**, because both are the same shape as
the bugs this project keeps finding -- a thing that works until something unrelated changes:

  * the check lifts the drag arithmetic out of canvas.js by bounding the region with
    `ev.stopPropagation()`, which was the last line of the handler until the diagnostic was
    inserted after it, at which point the extraction swept in `dragTrackingError` and
    `renderCanvas` and the check failed on a missing identifier;
  * then it located the offset with `js.find("const [wx, wy] = toWorld(ev);")` from the top of
    the file, which matched the *diagnostic*, since that uses the same expression and is defined
    earlier -- so it extracted the diagnostic and `px()` instead of the handler.

Both are now bounded by what they actually need: the search starts at `ng.onmousedown`, and the
region ends at the assignment. A bound chosen because it happened to be last, or a search from
the start of a file for a line that is not unique, works until it does not.

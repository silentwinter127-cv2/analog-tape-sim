fix the scope error that broke dragging outright, and stop trusting checks that build their own world

The console line was the whole answer:

    [atsim] canvas 2026-10-11 13:52 drag-offset-from-toWorld
    canvas.js:350 Uncaught ReferenceError: toWorld is not defined
        at ng.onmousedown (canvas.js:350:24)

**The build stamp did its job.** It proved the browser was running the current file, so the
cache was not the problem -- which is the thing three previous recordings could not settle.

**Then it showed the fix was worse than the bug.** `toWorld` is a `const` local to `initCanvas`.
The node's mousedown handler is created in `renderCanvas`, a different top-level function, so the
identifier does not exist there. Every mousedown threw, and dragging stopped working entirely:
a node that slid away from the cursor became a node that could not move. The arithmetic was
right and unreachable.

**The check could not see it, and that is the part worth keeping.** It extracts the handler's
code and runs it with `toWorld` supplied as a global -- and supplying the identifier is exactly
what the real page fails to do. A check that builds its own environment tests the environment it
built. It verified arithmetic it had made work.

The transform is now a module-level `toWorldFor(svgEl, ev)`, used by all four call sites, and the
closure-local duplicate is gone. One definition, one scope, no closure to be outside of.

**Five attempts at a scope check, four of them wrong.** The failure needed a check, but the first
four versions reported 174, then 15, then English words out of comment prose, then object-literal
shorthand. Every one was the check measuring the wrong thing -- short names recurring everywhere,
prose being scanned for identifiers, `{ name: n.name, dx: ... }` declaring names a `const` scan
cannot see. A regex approximation of a scope chain is not something to keep tuning.

What replaced it needs no scope model, because the failure has a sufficient condition:

    a module-level `function toWorldFor` exists
    no `const toWorld` is declared inside a function
    no handler mentions a bare `toWorld`

The original bug violates the first and the third. Three assertions about names that either exist
or do not, and it would have caught this on the first try.

The lesson, stated plainly: a check that reimplements or supplies its own dependencies can only
confirm the author's model of the problem, and the author is the one who is wrong. The check that
works reads the shipped artefact and asserts a property of it.

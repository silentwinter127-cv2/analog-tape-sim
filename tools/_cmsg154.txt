make `chroma_residue` reachable: it was forced to 0.35 by the presets every frame

**Measured, the parameter did nothing at all.**  With the cast fixed, setting `nv_chroma_residue` to 0.00, 0.35 and
0.95 gave **bit-identical output** -- hue spread 0.1891 and saturation 0.1950 in every case.  **A probe inside
`monochrome_green` shows why**: the value that reaches the term is **0.350 for all three settings**.

**The cause is the same one this file already records twice.**  `mode_spec` rebuilds the spec from the mode's preset on
every frame, and all three presets carried their own `chroma_residue` -- 0.35 for `nightshot`, 0.90 for `super_nightshot`,
1.0 for `colour_slow_shutter` -- **so the user's value was overwritten before it was read.**  It is the same defect as
`ir_response` being forced by this very function, and as `accumulate` being forced to 1 by mode 1, both of which are
already in the comments above the presets.

**And the argument for removing it is the one already made for `ir_response`**: *a preset that overrides a physical
control is a preset that removes the control.*  The residue is how much of the picture's own chroma survives the mono
display, which is a property of **removing the IR-cut filter** -- the camera, not the mode -- **and it is the quantity the
three real segments disagree about most**: their red share runs **0.2892 / 0.2339 / 0.2011, a factor of 1.44**, which is
exactly why it has to be tunable rather than fixed.

**Measured after the fix:**

    configured   the value the term receives
    0.00         0.000
    0.35         0.350
    0.95         0.950

**and it now moves the quantity it is named for:**

    residue 0.50   hue spread 0.6966   saturation 0.1857
    residue 0.70   hue spread 0.6019   saturation 0.1805
    residue 0.95   hue spread 0.6959   saturation 0.1859
    the footage    0.117-0.552         0.310-0.339

**so the hue spread reaches the footage's range** -- and **the trade-off reported last round was largely an artefact of
the inert parameter**: the saturation cost of widening the spread is **0.1950 -> 0.184**, not the 0.2093 -> 0.1589 that
the single-knob sweep showed.  **Two controls that overlap is worse than one that works, so `cast_variation` defaults to
0.0** and the model's behaviour is unchanged by default; both are now reachable for whoever tunes them.

**An honest note on the values**: the hue spread does not move monotonically with the residue (0.50 gives more than 0.70),
so it is a control to be tuned against the footage rather than set from a formula, and **this round does not claim a
fitted value**.

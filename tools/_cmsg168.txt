**The four "broken checks" were my own measurement error.**  I had swept the saturation point against my own downlight --
a black frame with a bright disc -- and the drain's ring survived at every setting.  **The check uses a LIGHT CEILING:
background 0.62 with the disc at 2.6.**  With that configuration the boundary is exact:

    sat_stops   white point   the ring at drain 0.15 / 0.25 / 0.35
    0.00        1.0000        0.02534  0.04223  0.05913    ring OK
    **0.30        0.8123        0.03610  0.05998  0.08387    ring OK -- and STRONGER**
    0.40        0.7579        0.00821  0.01269  0.01717    ring OK, decaying
    0.50        0.7071        0.00000  0.00000  0.00000    **ring GONE**

**and the mechanism is that the white point falls to the background's own level**: at 0.50 it is 0.7071, so the 0.62
ceiling is compressed flat and the drain has no gradient beside the saturated core to pull down.  **So 0.30 is the
largest value that keeps the ring, and there the ring is not merely present but stronger than at 0.0** -- the drain acts on
a neighbourhood that the lowered white point has brought closer to saturation.  **The trade I had reported did not exist;
what existed was a sweep run in the wrong configuration**, which is the same fault this work has recorded six times.

**The one remaining failure had a real cause and a principled fix.**  With `saturation_stops = 0.30` applying always, the
suite caught that **the scanline structure began costing light** (the frame's mean varying by 0.00275 across the four spot
sizes) -- a property verified on a configuration with no night vision in it at all.  **Lowering the white point is a
statement about *this sensor's saturation*, and the mode it was fitted to is NightShot**, so it now applies only while
`nv_mode` is on.  **163 checks pass.**

**And the highlights now match the footage:**

replace two checks that could not fail, delete the dead function they tested, and measure line_jitter

The verification audit found two checks certifying things they could not see, and one function that
no shipped path used. All three were verified before acting.

**A check testing dead code.** `check_node_positions` tested `_preset_columns_to_pixels`, which
turned out to have **no call sites**: the live conversion is `Graph.normalise_positions`, called from
`App.__init__` and `graph_load_preset`. Grepping found six references -- the definition, four inside
the check itself, and one in a comment. So the check verified a helper nothing used, and if the live
conversion had broken it would still have passed. The dead function is deleted, along with the two
constants only it read.

**A check defeated by substring.** `check_graph_build_positions` decided whether both server routes
normalise by searching the server *source* for `".normalise_positions()"`. An auditor deleted the
start-up call and the test stayed true, because the substring still matched at the definition site;
its `or` for the preset route was satisfied by the name of the dead helper. That record is replaced
by assertions about a real `App`: build one, load a preset, and check what the graph contains. A
substring cannot satisfy "6 nodes, x spread 1120 px, all flagged as pixels", and removing the
conversion from either route fails it.

**`line_jitter` was covered by nothing.** The row-time-base check measures row shifts from the
rendered planes, but every configuration it builds sets `line_jitter` to 0, and no other check
exercises it. An auditor constructed a `_apply_timebase` that applies only the row-time-base field
and never the line phase -- making `line_jitter` completely inert in the picture -- and the suite
stayed green. Measured directly, the mechanism is in fact alive: rendered per-row shift std goes
0.4457 (off) -> 0.8248 (at the default) -> 1.1708 (at maximum). So it was a gap in the check rather
than a defect in the code, but it is the kind of gap that lets a real defect through. A record now
measures it from the render, with `line_jitter = 0` as the negative control.

**Two attempts at these edits failed the same way**, which is worth recording because it is the
project's recurring shape. Both bounded the region to be replaced by searching for a blank line, and
the two functions involved are adjacent with none between them -- so both cuts ran into the following
function's docstring and left it unterminated. The third attempt matched the exact source text and
asserted it occurred once. Line arithmetic on a file whose contents are known only approximately is
not a safe way to edit it; the same lesson was recorded when an earlier duplicate-removal deleted 77
lines and then an entire neighbouring definition.

78 checks pass, 15 presets render, selftest ALL CHECKS PASSED at 11.8 fps.

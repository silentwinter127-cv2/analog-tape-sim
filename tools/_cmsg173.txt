**The user's report "导入失败 配置里没有 params" was two independent faults, and both are real.**

**1. The file used `layers` where the importer reads `params`.**  `atsim/web/server.py`'s `import_config` reads
`payload["params"]` and raises its own message when it is missing -- so `settings.json` was generated in a shape the
importer could not read.  **`tools/write_settings.py` now writes both keys from the same dict**, so they cannot disagree:
`params` for the importer, `layers` for a person to read and diff.  Verified end to end: **POST to `/api/import` returns
HTTP 200 and the live project afterwards holds the file's values** (`nv_mode 2.0`, `saturation_stops 0.3`,
`nv_exposure_trim -0.1`, `nv_chroma_residue 0.15`, `nv_highlight_saturation 4.0`, `nv_illuminator 1.2`).

**2. And the server could not import ANY configuration that omits `seed`.**  `import_config` built a fixed payload with
`"seed": payload.get("seed")`, so an absent key arrived as `None` and `set_project`'s `int(payload["seed"])` raised
`TypeError: int() argument must be a string ... not 'NoneType'` -- **with the values never applied at all**.  Fixed in two
places, because either alone would leave the fault reachable from the other direction:

  * `set_project` now tests `payload.get("seed") is not None`, and the same guard is applied to `standard` and `name`, so a
    payload with `None`-filled gaps cannot set `str(None)` or an empty name;
  * `import_config` builds its forwarding dict from **the keys the file actually carries** rather than from a fixed list.

**A key that is absent should be absent** -- that is the principle, and the second fix is the one that expresses it.

add device individual variation: one machine, not a model number

The note's first and most important dimension. Until now the model had one "VHS" and one "camcorder"
that every unit shared, so a machine from a dry cupboard and one that spent ten years in a car boot
produced the same picture. Real machines of one model differ because components have tolerances: two
CCDs from one batch differ in dark current, two lens assemblies differ in centring, two servo boards
differ in gain.

**Represented as a property of the parameter, not as a new layer.** Each `ParamSpec` now carries a
`unit_spread`, the fraction by which a particular unit may sit from nominal. A schema layer would have
needed `LAYER_LABELS`, `STAGE_LAYERS`, `STAGE_ORDER` and the UI's layer list updated in six places,
and would not correspond to any part of the signal chain; a separate variation map would put the data
about *which* parameters vary away from the parameters. The field costs no plumbing -- `define(**kw)`
already forwards unknown fields to the dataclass -- and needs one pass in `resolved_params`.

**Thirty-five parameters declare a spread, and the omissions matter as much as the inclusions.** A
spread is written only where there is a reason to expect unit variation: alignment and gain trims, per
die component tolerances whose effect is known, and wear (which depends on use rather than on
manufacture). Artistic parameters -- `halation`, `lens_flare`, `highlight_tint` -- are left at zero
on purpose, because an invented spread is worse than none: it looks like provenance and stops the next
person checking. The table carries the reason next to each number.

**Three properties, all asserted:**

    no identity       -> every parameter unchanged, so no existing preset or capture shifts
    same serial       -> identical parameters, so a fault stays reproducible
    different serial  -> 35 parameters differ, largest being head_wear at 84% and
                         burst_phase_error at 53%

The first is the one worth testing hardest, and it failed on the first attempt: `draw()` drew a
deviation for every spread parameter regardless of the identity, so an anonymous unit perturbed
everything. That is the failure that would have invalidated every calibration silently, with the 78
existing checks starting to fail for reasons unrelated to what they test. An empty identity now draws
nothing, because a serial number is a statement that this is a particular machine and without that
statement the model must be the nominal one.

The identity is a `Project` field, so it is saved and loaded with everything else -- a unit that is
not saved is a unit that changes when the project is reloaded, which would break reproducibility.

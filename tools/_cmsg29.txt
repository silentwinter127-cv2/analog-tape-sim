add the two positions for the character generator, and the subtitle editor

The two things asked for, in the order that made them safe: the position first, because it is a signal-chain
change, then the interface on top.

**The generator now writes in one of two places, and they are physically different.** A camera burns its OSD
over the video signal after the picture is formed, so tape damage that happens later lands on the picture and
not on the text. A titler records onto the tape, so the recorder's dropouts, head wear and timebase errors
damage the text as well. Measured with heavy damage: at the camera position the text keeps its painted value
to within 0.00021 while the picture around it moves by 0.01599; at the titler position the text is dragged by
0.32349 against 0.03503 for the picture -- a ratio of 9.2 inside the text against 0.01 outside it. Both halves
are asserted, so an implementation that damaged everything equally, or nothing, fails.

**The position is a slot, not a reordering.** `STAGE_ORDER` is used as an *index* in thirteen places -- cache
lookups, the dirty bookkeeping, the plan output -- so reordering it per project would mean making the whole
cache layer order-agnostic. Instead the chain keeps its fixed order and the stage is instantiated in the slot
the parameter selects, with exactly one instance either way: a stage that ran in both positions would write
its output into one buffer and leave the cached frame at the other slot without the text, and the two would
disagree about what a frame contains.

**And the editor, which needed two things the schema panel cannot express.** Every other parameter in this
model is a number, so the panel renders one slider per number; the subtitle text is multi-line and the font
is a named choice. Only those two get a bespoke control -- the numeric subtitle parameters (cell height, row
and column offsets, colour) stay in the parameter panel. The push is debounced because a subtitle is typed
rather than dragged, and the field is never overwritten while it has focus, so the server's echo cannot fight
the user's typing. A live warning names the exact characters the chosen font cannot draw, and the engine's
own authoritative list is shown after a render.

**Five faults, and four of them were the same fault: reading a value at the wrong moment.**

  * **`build_chain` read `self.params["overlay"]["at"]` correctly, but the *first* probe of the position
    looked at `STAGE_ORDER` rather than the chain** -- so a correct chain failed the check, because the
    static tuple puts the tape at a different index than the chain does when the overlay moves;
  * the editor sent `{"overlay": {...}}` where `App.set_project` reads `payload["params"]`, so the values were
    **silently ignored** and the panel's own state came back from a payload it had failed to change. The file
    has a second entry point, `set_levels`, which *does* take a bare layer mapping, so the wrong one fails
    silently in both directions;
  * `App.osd_report` was never initialised, so the payload raised on a missing attribute before the first
    frame;
  * the report was captured **before** the frame was rendered, when the chain had not been built and
    `r.stage` was empty -- so it was always `{}`. This is the fourth time in this session that a value was
    read at the wrong moment: the exposure loop's state was read before it was stepped, an overlay was placed
    after a `return`, and a per-frame push happened before the stage it targeted had been built;
  * and the first version of the position check measured the wrong variable, deriving its text mask from one
    of the two positions. At the other position the mask covered the wrong pixels, the numbers came out
    reversed, and the mask grew to 15853 pixels of 76800 -- because placing the overlay before the tape
    changes the tape's plan and therefore every pixel. Fixing the damage and varying the position measures
    the difference between two placements, which is real but is not the claim; fixing the position and
    varying the damage measures the claim.

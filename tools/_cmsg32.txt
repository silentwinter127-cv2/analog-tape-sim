fix the subtitle being stored where nothing reads it: accept both payload shapes

**The fault.** The saved project contained

    "overlay": {"enabled": 0.0, "text": "", ...}          <- the real layer, untouched
    "params":  {"overlay": {"enabled": 1, "text": "1"}}  <- a layer literally named `params`

so the text was stored where nothing reads it, `project_dict` reported the real layer at its defaults, and the
panel's own state came back from a payload it had failed to change. Every visible signal said the interface was
working.

**The mechanism.** `App.set_project` merges `payload["params"]` per layer -- that is the server's convention,
and `set_levels` wraps its argument exactly that way -- but the `/api/project` route passes the body straight
through, so the *client* has to nest. A client sending the bare `{"overlay": {...}}` therefore sets a layer
named after the payload key, and a client sending an already-nested patch produces the double-nesting above.
Measured: the bare form left `overlay.enabled` at 0.0 with no error and no warning.

**Two fixes.**

  * `set_project` accepts a bare layer map as well as the nested form, detected by the payload naming a known
    layer at the top level, and unfurls a doubly-nested one. A caller that sends layers directly is making a
    reasonable mistake and silently discarding the values is the worst possible response to it. All three
    shapes now set the layer, verified on the real `App`;
  * the editor's fallback path also nests its patch. It was dead code while `app.js` is loaded, and it sent the
    bare form -- a trap rather than a fallback.

The stored projects were repaired too: one carried the stray layer and its values were moved into the real
layer, since the real layer was still at its defaults. The other 122 have no such layer.

**Three wrong explanations, and the third one is worth recording because I acted on it.** I read a truncated
`grep` as showing two definitions of `pushProject`, concluded the second shadowed the first, and changed the
server to compensate -- for a client bug that did not exist. The function is defined once and always wrapped
correctly. Reading the four lines directly, rather than the tool's summary of them, would have taken ten
seconds. This is the same failure the project keeps recording in other forms: a conclusion drawn from an
instrument without checking the instrument.

**And one measurement that was correct but incomplete.** The earlier check asserted that
`setProject({ params: patch })` appears in the editor -- which it did, and the editor still did not work,
because the string being present says nothing about whether it is the definition that runs. The new check posts
all three shapes and asserts the layer changed, which is the property that matters.

Verified on the live server: typing a single character gives `overlay.enabled=1.0, text='1'` with one glyph
drawn, and a two-line subtitle gives 21 glyphs and a 0.037 change in frame luma with nothing missing. The
exported frame shows both lines rendering correctly.

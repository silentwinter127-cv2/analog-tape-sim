repair the client, which an insertion had cut in half

**The apply button was not below the fold. The entire client was broken.**

Four turns ago I added two colour helpers, anchoring the insertion on the comment
`// --- the style templates, which are the reference looks as one click`. That comment sits **inside**
`osdPanels`, and a function declaration is not a statement that can be nested there without consequence:
`function hexToRgb() {}` at that point **ended `osdPanels` early**, and the roughly 170 lines after it -- still
indented four spaces -- became top-level statements referring to `el`, `host` and `osdEls`, none of which exist
at that scope. The IIFE threw while loading, so **nothing** in `session_ui.js` was built: no apply button, no
colour pickers, no alignment controls, no panels.

The user saw a panel whose first row contained one checkbox and reported the button missing. I pinned the row
correctly, and it did not help, because the row's own builder was one of the things that had stopped running.

**`node --check` passed the whole time.** The file was syntactically valid; it was wrong only at run time. Every
edit in this project is meant to assert that it landed inside the intended function, and this one did not -- the
anchor was a comment in the middle of a body, which is exactly the trap the rule exists for.

**The check is structural, and it was wrong twice before it was right.** The first version looked for a `return`
to bound each function; almost every function ends with `}` instead, so the walk crossed each boundary and the
check failed on **twenty-eight perfectly good functions**. A check that fails on everything carries no more
information than one that cannot fail, and both are the fault this project has now found repeatedly. The
boundary now comes from the **balanced braces**, which is what delimits a function in JavaScript, and the
assertion is exact: no line inside a function's braces may sit at column zero.

**And it was proved to fire.** Reintroducing the exact fault in a scratch copy makes it report
`osdPanels (line 577) has a top-level line at 607` -- one function, the right one. A check that has never been
seen to fail is not evidence, and this project has produced too many of those.

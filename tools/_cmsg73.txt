fix the root cause: the recursive band-limit filter never reached steady state, so it attenuated DC

**The fault, and it underlay everything chased over the previous turns.** `apply_one_pole` ran
`scipy.signal.lfilter([a], [1, -(1-a)], out, axis=axis)` from a **zero initial state**, so every row began at zero and
climbed. The time constant is `1/a` samples, and at the default 0.75 MHz cutoff on an 11.33 MHz pixel rate `a` is
**7.17e-7**, so the time constant is about **1.4 million samples** -- against image widths of one to two thousand.
The filter therefore **never reached steady state**: its response to a constant was

    0.30 MHz -> 0.01679      1.7% of the signal survives
    0.50 MHz -> 0.15613
    0.75 MHz -> 0.46942      the default: 53% removed
    1.00 MHz -> 0.68794
    1.50 MHz -> 0.86103
    6.00 MHz -> 0.99025

**A one-pole lowpass's steady-state DC gain is exactly 1.** This one measured whatever fraction of the transient
happened to fit inside the row, and it **depended on the picture's width** -- so a preview and a full render behaved
differently, which is a fault in its own right.

**And the docstring already recorded the mirror image of it.** A hand-written accumulator that "re-seeded the state
from the first sample of every row" made "the filter never leave its startup transient -- **DC gain looked perfect**
while the AC response collapsed". The answer chosen then was `lfilter`, whose zero state made the **DC** wrong and the
AC right. Seeding the state makes both correct.

**Fixed by seeding each row's state to its first sample**, which is what a filter that has been running on a signal
does. Verified in a way that cannot flatter it -- the same measurement at three picture widths, because a correct
filter's DC gain does not depend on how wide the picture is:

    0.30 / 0.75 / 1.50 / 3.00 MHz  ->  1.00000  at widths 120, 1200 and 4800

**And the fix closes the faults that had been attributed to other things.** Measured with `tools/boundary.py`, on one
flat sodium-lit colour:

    the composite against an ideal one      max |diff| 0.627  ->  0.00816
    the player's recovered I                0.1638 (48%)      ->  0.3425    target 0.3435
    the rebuilt colour (blue)               0.2316            ->  0.0203    source 0.0184

    and stage by stage, R-B:                 +0.6365 (13% drift)  ->  +0.7148 (2.5% drift)

**Two checks had to be re-stated, and the reason is worth more than the numbers.** Both asserted *relationships*
rather than values, and both were passing because of the defect:

                        gain 1.0   gain 2.2   ratio    gain 0.1
    zero-state          0.43473    0.65723    1.512    0.08880     the old behaviour, which passed
    seeded state        0.53667    0.78769    1.467    0.10285     the fix

The un-normalised filter reduced the chroma, which shrank **both** terms of the normalised-saturation ratio and
pushed it from 1.467 to **1.512** -- over a threshold of 1.5. **So the checks were scoring an artefact of the bug:
the broken filter passed them and the correct one failed them.** The thresholds are now 1.4x and 0.12, set to what
the correct filter gives with a margin, and the reasoning is recorded **in the check itself** rather than in a commit
message, because **a threshold that a defect satisfies is worse than no threshold -- it reads as evidence.**

**Also normalised in the same file:** the Gaussian path of `lowpass_hz` is a truncated kernel with the same property
(`sum(exp(-k^2/2 sigma^2))` below one), and it is now divided by its tap sum. It is not the path this preset uses --
`constant_k` is -- but it has the same fault and other configurations select it.

**What remains, measured and not fixed.** On a clean modern photograph the drift is much reduced but not gone, and
the two paths differ:

    no composite chroma (digital component)   colour drift 0.11390
    the project's defaults (DV on)            colour drift 0.27542

The DV path skips the composite chroma entirely, so its smaller drift is consistent with this fix, and **the 0.114
that remains is a separate cause** -- the next thing to attribute, with the same stage-by-stage tool that found this
one.

161 checks pass, selftest clean, and the filter's DC gain is exact at every cutoff and width.

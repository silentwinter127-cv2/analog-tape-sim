CRT moisture, a connector test bench, and the node-drag fix

**CRT interface moisture**, the last junction in the chain. A CRT's signal path is short and
entirely analogue -- connector, video amplifier, cathodes, with the yoke driving deflection --
so damp affects the *amplifier* rather than the signal reaching it, and produces three effects
that look nothing like tape damage:

  * the **bias shifts**, so the black level moves and the picture washes out rather than
    gaining noise. A damp set looks pale, not grainy;
  * the **three channels drift apart**, because each cathode has its own amplifier. Measured
    with the age parameter: the cast spread goes 0.0336 to 0.1070 between a new set and an
    aged one, while the bias moves only 0.0346. That is why the same damp room washes out a
    new set and tints an old one, and it is a property of the display rather than a cast in
    the recording;
  * the **deflection becomes unstable**. The yoke is the highest-current part of the set, and
    a supply dragged down by leakage makes the scan shrink and breathe -- measured, the raster
    scale runs 0.700, 0.677, 0.669, 0.681 over 1.2 seconds.

That last one is the diagnostic part: it is the **only** fault in the whole model that can
move the edges of the raster. A tape cannot bend the picture, so if the frame edges are
moving, the fault is in the display and nowhere else. The check asserts the geometry
separately for exactly that reason -- one that only looked at the level would pass a model
with no geometry at all.

**The connector test bench**, at `/connectors`. Every interface degraded side by side against
a clean baseline, one interface per tile, with the physical mechanism written under each
rather than the name of the effect. It is the interface form of the "import a test image and
see everything on one screen" request.

Building it found a defect that would have made it useless. `/api/project` **merges** a patch
into the current parameters rather than replacing them -- measured, setting only `rf_present`
left `hdmi_present` at 1.0 from an earlier request. So a tile posting only its own interface
renders every interface set by the tile before it as well, and its picture does not match its
caption. Every tile now posts the complete neutral set plus its own, with all fifteen
connector parameters and all three CRT ones named, because a missed parameter stays live from
the previous tile. `verify_bench.py` asserts that each tile carries exactly its own
configuration and nothing else.

**Chasing that defect cost three wrong conclusions, all mine.** The first script saw groups of
byte-identical frames and read a stale cache; the second, with a pause before each request,
saw every configuration distinct and stable; a third showed no lag either way. All three were
measuring my own request sequence rather than the engine. The endpoint merges, so consecutive
patches accumulated each other's damage until two neighbours happened to sum to the same
picture -- which looked exactly like a cache that had not invalidated. The rule this project
keeps relearning held again: suspect the instrument, and here the instrument was the script.

**The node-drag fix.** Nodes jumped while being manipulated for two reasons. The flag marking
a position as being in pixels was set as `_px` on grab while the coordinate function and the
save handler both read `px`, so the mark made on mousedown was never seen by either. And a
dragged position could be re-read from a server payload and put through the grid-to-pixel
conversion again. The flag name is now consistent, and dragged nodes keep their coordinates
against a later payload. A heuristic cannot be made to separate a grid position of (8, 0) from
a pixel position of (8, 0) -- the units have to be carried, not inferred.
